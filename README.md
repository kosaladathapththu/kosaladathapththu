# System Integration Approach

<div align="center">
  <img src="./assets/system-flow-ultimate.svg" width="100%" alt="Animated system integration workflow" />
</div>

### How I usually approach a software problem

1. Understand the real business or operational need.
2. Identify users, roles, data sources, actions, and risks.
3. Design the main screens and data flow.
4. Build a clear frontend structure.
5. Connect APIs, databases, telemetry, or automation flows.
6. Add validation and useful error messages.
7. Test normal cases and failure cases.
8. Improve performance, usability, and deployment setup.
9. Document the final workflow.
10. Continue improving after real user feedback.

### Solution

I designed a React application connected to Google Apps Script and Google Sheets. The system organizes customer profiles, AC units, service records, installations, payments, and complaints.

### Important features

- Customer management
- AC unit records
- Installation tracking
- Service lifecycle tracking
- Payment status
- Complaint management
- Technician type
- Outsourced payment information
- Automatic reminder-email workflow
- Dashboard summary cards
- Edit modals and record updates
- Netlify deployment

### Engineering lessons

- Convert a real business process into clear data tables
- Keep frontend and backend field names consistent
- Design update operations carefully
- Handle dates and payment states clearly
- Build for non-technical business users

## 2. Renewable Energy Dashboards

### Problem

Operational plant data can be complex. Users need quick visibility into power, equipment conditions, alarms, trends, and availability.

### Solution

I worked on React dashboards and data integrations for solar, hydro, and wind power monitoring. Node-RED and ThingsBoard supported data flow and telemetry visualization.

### Example wind telemetry

```json
{
  "plant_active_power_kw": 0,
  "plant_reactive_power_kvar": 0,
  "plant_voltage_avg_v": 0,
  "wind_speed_avg_ms": 0,
  "wind_direction_avg_deg": 0,
  "plant_daily_kwh": 0,
  "turbines_running_count": 0,
  "plant_availability_pct": 0,
  "plant_fault_count": 0,
  "plant_warning_count": 0,
  "grid_frequency_hz": 0
}
```

### Important engineering concerns

- Accurate field mapping
- Clear units and labels
- Reliable refresh behavior
- Safe handling of operational controls
- Visible warning and fault states
- Responsive layout
- Easy deployment on plant computers
- Avoiding unnecessary interruption to live systems

```text
01. Understand the need
        ↓
02. Define users, roles, data, and risks
        ↓
03. Sketch screens and data flow
        ↓
04. Design the database or API contract
        ↓
05. Build reusable frontend components
        ↓
06. Connect backend services and integrations
        ↓
07. Validate inputs and handle errors
        ↓
08. Test real workflows
        ↓
09. Deploy and monitor
        ↓
```
